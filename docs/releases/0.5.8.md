# NimbusDNS 0.5.8

DHCP lease transitions and cleanup now share a transaction lock, so an address cannot return to the free pool while a lease or outstanding offer still owns it. Expired leases produce fresh, requestable offers. Requests selecting another DHCP server are ignored, and unknown INIT-REBOOT clients on the same subnet no longer receive destructive NAKs.

DECLINE validates address ownership and preserves conflict exclusions for the lifetime of the server process. Exclusions are intentionally not persisted across restarts. Lease persistence is ordered with packet processing. Reply delivery preserves relay addresses, uses the client address for renewals, and handles socket backpressure without a busy loop. Logs now include transaction IDs and response destinations.

All direct Rust dependencies use their individually verified latest stable releases, including the Argon2/password-hash API migration. Existing password hashes remain compatible. See [the complete dependency review](0.5.8-dependencies.md) for all 300 registry packages and constrained transitive versions.

Release builds use Cargo.lock. Docker and GitHub releases wait for tests, and versioned multi-architecture manifests reference the matching versioned amd64/arm64 images.

The previously observed Raspberry Pi reconnect issue is not conclusively attributed to these bugs; DHCP packet capture during a recurrence is still needed to establish that connection.
