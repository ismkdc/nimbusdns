# NimbusDNS 0.5.12

Robustness release. Every fix below came out of a stress and fuzzing run against 0.5.11 (dnsperf at ~300k qps, malformed DNS and DHCP packets, mutation fuzzing, TCP connection exhaustion, slowloris, DHCP starvation and pool exhaustion) and has a regression test that fails without it.

## DNS

**One client can no longer stall DNS for the whole network.** In-flight queries were capped globally (`max-concurrent-queries`, default 150) and a query to an upstream that never answers holds its slot for the full 5 s upstream timeout. About 300 such queries from a single device — or ordinary traffic while an upstream was slow — used every slot, and every other client's queries were dropped for 5 s at a time. There is now also a per-client cap, `max-concurrent-per-client` (default 64), and the global default is raised to 1024. A client that fills its own share only blocks itself.

**TCP pipelining (RFC 7766).** Only the first query on a TCP connection was answered; the connection was then closed with the rest unread, which made the kernel send a RST that could discard the first answer too. glibc sends A and AAAA back to back on one connection when it falls back to TCP, so those lookups failed. All queries on a connection are now answered in order (up to 100 per connection, 10 s idle timeout as before).

**Rate-limited queries no longer flood the query log.** Every refused query was written to the log, so one client over its rate limit pushed hundreds of thousands of rows a second into SQLite: a 20 s flood wrote ~700 MB and kept the writer busy for minutes. Now only the first refused query per client per second is logged. The same flood now leaves a 2 MB database and the server idle immediately afterwards.

**DNS responses (QR=1) sent to the server are ignored** instead of answered, so two servers cannot bounce packets at each other and the server is not a reflector for them.

**Forwarded answers set RA and clear AA.** Answers relayed from an upstream kept the upstream's flags, so an upstream that sets AA (or leaves RA clear) made nimbusdns look authoritative or non-recursive to clients.

## DHCP

**DHCP works when nimbusdns is not the gateway.** Replies were sent from, and identified the server as, the configured `router` address. That only worked when nimbusdns ran on the router itself; on any other host the kernel refused to send from a foreign address ("Network is unreachable") and no client ever received an offer. The server now uses its own address on the served interface (or, without `interface`, its local address in the pool's subnet) for the IP source and option 54; `router` is only the gateway handed to clients. Installs on the gateway see no change.

**A packet with `hlen` above 16 no longer panics.** `dhcproto` slices its 16-byte `chaddr` by `hlen`, so one crafted packet panicked the packet task (and would take down the whole process under `panic = "abort"`). `hlen` is now checked first.

**DHCPINFORM is answered** (RFC 2131 §3.4): a client that already has an address gets DNS, router and domain in an ACK with no address and no lease times.

**Full-size DHCP packets.** The receive buffer was 1 KiB, so larger requests (many options, PXE, vendor class) were truncated and failed to decode; it is now 1500 bytes.

## Build

The builder image moves from Debian 12 (`rust:1-bookworm`) to Debian 13 (`rust:1-trixie`), matching the `distroless/cc-debian13` runtime image.

## Upgrading

Drop-in image replacement; `nimbus.toml`, databases and DHCP leases are used as-is. If your config sets `max-concurrent-queries = 150` explicitly (older templates did), raise it — 1024 is the new default.
